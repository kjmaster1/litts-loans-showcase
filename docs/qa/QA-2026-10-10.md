# QA pass — 10 October 2026

Scope: the whole app, on a local copy (production touched only by read-only header checks
and read-only queries). Method: role-by-role authorization matrix, sign-in/session flows,
hostile and malformed input, odd URLs, double submits, 320 px reflow (WCAG 1.4.10),
keyboard use, time zones/locales, figures across pages, page speed, axe-core (WCAG 2.2 AA).
Harness: Playwright with saved per-role sessions (one sign-in per role, no fixed sleeps).

## Findings and fixes

| # | Severity | Finding | Fix |
|---|---|---|---|
| 1 | High | Sign-in (and change password, 2FA set-up, 2FA code, backup codes, step-up) had no form method: submitted before JavaScript loaded, the browser sent `GET /sign-in?username=…&password=…`, putting the password in history and logs. ~20 other forms would put notes/reasons in the URL. | Every client form is `method="post"`; the four search/filter forms are `method="get"` (harmless, and they now work without JavaScript). |
| 2 | Medium | `/loans?sort=__proto__` (also `constructor`, `toString`) crashed the Loans page — `in` sees inherited keys. | `Object.hasOwn`. |
| 3 | Medium | Validation messages were Zod's developer wording ("Too big: expected string to have <=2000 characters", "expected number, received NaN"); limits weren't visible. | `friendlyIssue()` (`src/lib/validation-messages.ts`) in `runAction`; schema-written messages kept. `maxLength` + countdown on note boxes. |
| 4 | Medium | Loan page and Bank imports overflowed a 320 px screen; long unbroken text in notes/reasons overflowed by up to 28,000 px. | Detail rows stack below `sm`; imports column `min-w-0`; user text wraps anywhere. |
| 5 | Medium | Dashboard "Expected to receive" ≠ forecast "All still to come". Cause: Expected counted the State's share of instalments still to come (Litt's never receives it — $7,355 live); the forecast trusted the phone's "N completed" count over the books (early repayments, missed payments — $6,861 the other way live). | One calculation (`remainingPrincipal` / `loanInflows`, `src/domain/forecast.ts`): the books decide how much is owed, the schedule how it splits; missed money is due with the next instalment, early repayment drops instalments from the end. Both figures now come from it — gap $0 (live: $1,440,320). |
| 6 | Medium | A cut-off phone-card paste (4 lines) was read as a whole card and the preview claimed 14 loans had moved. | A card without a broker rate or "N/M complete" line is refused ("Card 1 … looks cut off"); all 344 cards on record have both. |
| 7 | Low | Settings asked for an authenticator code before checking the numbers. | Rules checked in the browser first (same schema). |
| 8 | Low | A promise to pay / follow-up could be dated in the past. | Refused on the server; date pickers have `min` = today. |
| 9 | Low | Not-found pages answered HTTP 200 (route-level `loading.tsx` streams first, fixing the status). | Loading screens replaced by a top progress bar (`NavigationProgress`); pages render fully and return real 404s. |
| 10 | Low | "Add data" items read as "Paste from tabletA mortgage's sale agreement". | Title as the name, description via `aria-describedby`. |
| 11 | Low | 2FA set-up password form had no username field for password managers. | Hidden `autocomplete="username"` field. |
| 12 | Low | 35 Tab presses to reach the first loan. | "Skip to the list" right after "Skip to content" on list pages (2 Tabs). |
| 13 | Info | No `robots.txt`; obsolete `interest-cohort` in Permissions-Policy. | `robots.txt` (disallow all); `browsing-topics=()`. |
| 14 | Info | Step-up dialog showed the old error while checking a new code. | Error hidden while checking. |

All re-tested in the browser after the fixes (PASS), axe-core clean in both themes,
regression tests added (cut-off paste, past dates, messages, forecast cases).

## What passed first time

Security headers (strict nonce CSP, HSTS preload, frame-deny, nosniff, no-store,
noindex); authorization for all four roles including direct URLs and report/export
routes; officers can't see others' loans or mortgages; direct sign-up API refused;
identical message for wrong password / unknown user; 7 bad attempts → rate limited;
open-redirect attempts ignored; session cookie HttpOnly/Secure/SameSite=Lax; back after
sign-out; used invite refused; half-enrolled accounts forced to finish 2FA; idle warning at
13½ min and sign-out at 15; staff-management limits; stored HTML never executes; double
clicks don't duplicate; bad pastes/imports explained; LA time zone renders without
warnings; figures consistent across pages; pages respond < 140 ms locally.
