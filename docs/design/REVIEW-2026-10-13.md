## Full review — 13 October 2026

The owner asked for a full, heavily scrutinising review of the design and implementation. This is
what was found, what the owner decided, and what became of each point.

**How it was checked:** lint, typecheck, all tests with coverage (552 passing; 87% of lines, 77%
of branches), `pnpm audit`, and a read of auth, permissions, step-up, audit, ledger, import, loan
sync and matching, commissions, staff, export, CI, backups and the Vercel project (Node 24.x, no
runtime errors in the week before). No visual UI pass: two UX reviews had just been done
(`UX-PASS-2026-10-11.md`, `UX-REVIEW-2026-10-12.md`). Route timings need Vercel's paid
Observability Plus, so performance points rest on the code.

**What was already strong:** the books are protected by the database itself (append-only journal,
deferred balance check, one-sided lines, immutable raw bank rows); imports are atomic, idempotent and
wallet-checked; every action authorises itself; the audit trail is chained and anchored nightly.

**Owner's answers:** the live app did connect as the Neon owner; for commission on late money, "do
whatever you recommended"; loan officers may keep claiming unassigned loans for themselves.

| # | Finding | Outcome |

| 1 | **Commission silently lost** for interest (and banker fees) dated in a week that was closed before the bank export covering its last days was imported, or linked by hand afterwards: weeks read bank rows by date, closing only checked the calendar | **Fixed.** Closing needs a bank row dated after the week ended (`bankCovers`; the Close button says why). Late arrivals are carried into the next open week, labelled, and paid exactly once (`lateArrivals`). `COMMISSIONS.md`; `commissions.test.ts`. |
| 2 | **No least-privilege database role** (SPEC §8 promised one): the app, backups and health check used the owner login, which can switch the append-only triggers off | **Fixed in code; switch-over pending (owner).** Migration 0030: `litts_app` (rows only; no UPDATE/DELETE on append-only tables, no DDL/TRUNCATE) and `litts_readonly`. Steps for passwords and connection strings: `DEPLOYING.md`, "Database roles". `database-roles.test.ts` pins the grants against the triggers. |
| 3 | **Step-up lockout bypassable** by sending codes in parallel (read-then-write counter), no per-IP limit on the Server Action, and a used code could step up again | **Fixed.** Checked with the `two_factor` row locked (parallel attempts each count: 8 at once → exactly 5 counted, then locked); the accepted time step is stored (`staff.step_up_counter`, migration 0029) so a code works once. `staff.test.ts`. |
| 4 | `listLoans` **stopped at 500 rows**, and reports, expected losses and the borrower directory total it: the oldest loans would have dropped out quietly (~4 years away) | **Fixed.** No cap (`list-limits.test.ts`, 520 loans). Output unchanged (fixture tests). |
| 6 | CI: actions pinned by tag in jobs holding the owner DB URL and Vercel token; no Dependabot or `pnpm audit`; Node 22 in CI vs 24 in production; browser tests didn't gate deploys | **Fixed.** Actions pinned to commits; `.github/dependabot.yml`; `pnpm audit --prod --audit-level high` first in CI; Node 24 in CI, `engines` and `@types/node`; `e2e.yml` is called by CI and deploy waits for it (~12 min). `xlsx` (SheetJS CDN) is outside the tooling: checked by hand. actionlint clean. |

**Database role switch-over (#2): done the same day.** The Neon integration locked Vercel's
`DATABASE_URL` (and put the owner login in the app's environment), so it was disconnected from the
project and the variable added by hand. The first deploy carried the read-only string and every write
failed for about 20 minutes; the smoke check added that afternoon (`/api/auth/get-session` touches the
database) caught it, and a redeploy fixed it. Confirmed: the app connects as `litts_app`, the backup and
anchor as `litts_readonly`; the owner login is left only in `MIGRATE_DATABASE_URL` and `.env.prod-admin`.

Afterwards: 576 tests passing (+24), production build clean. The browser tests run in CI before the
next deploy; the two screens that changed (Close week's reason, Mark repaid's code prompt) aren't
covered by an existing browser test.
